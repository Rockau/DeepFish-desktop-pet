# 配音和对话接入

托盘的 **设置 → 语音与对话** 集中管理文本对话、录音识别、朗读和配音。本版调试使用的藤田琴音语音包来源为 [BV1odxs6wE5H](https://www.bilibili.com/video/BV1odxs6wE5H/)。请按发布者说明获取和使用语音参考与模型权重。语音包、权重和录音由使用者自行准备。语音分支的实现参考见[冰镐人的 DeepFish-voice](https://github.com/ICEAXEMAN/DeepFish-voice)。

## 配置已在本机运行的服务

1. 先按首页说明安装桌宠，并准备兼容的本机对话桥接服务。桥接目录需有 `chat_bridge.py` 和该服务生成的 `.bridge-token`。手上的服务如果只提供 GPT-SoVITS 的 `/tts`，仍需要对话桥接层来转接请求。
2. 将 [conversation.example.json](../conversation.example.json) 复制为插件根目录的 `conversation.local.json`。将 `legacyRoot` 改成桥接目录，`python` 改成运行该桥接的 Python 路径。JSON 中的 Windows 反斜杠需要写成双反斜杠，也可以使用正斜杠。
3. 按需填写 `ollama`、`ttsLauncher` 和 `asrLauncher`。这些是本机可执行文件或启动脚本的路径。相关服务已常驻时，对应路径可留空。
4. 打开「语音与对话」刷新状态，再选对话模型和配音语言。用中文发一条简短消息，试一次中文或日语朗读，再试录音转文字。

| 项目 | 本地依赖 |
|---|---|
| 桌宠的 Agent 控制 | 可直接使用仓库编译出的 `FishPet.Mcp.exe`。 |
| 面板里的聊天 | 对话桥接监听 `127.0.0.1:18763`。`GET /health` 应返回 `ok: true` 和 `version: 2`，`/providers` 返回可用模型。Codex 模型按所选连接联网，本地模型可通过 Ollama 使用。 |
| 朗读和互动配音 | 本机 GPT-SoVITS 服务监听 `127.0.0.1:9880`，通过对话桥接提供琴音音色。指定中文或日语时，文本可由本机 Ollama 模型转换。 |
| 录音转文字 | 兼容的本机 faster-whisper-small 识别服务监听 `127.0.0.1:18766`，通过对话桥接传回识别文字。 |

桥接接口使用 `X-Companion-Token`，并提供 `GET /providers`、`POST /chat`、`POST /cancel`、`POST /tts` 和 `POST /asr`。字段可在 [Conversation.cs](../src/FishPet/Conversation.cs) 核对。桥接、配音模型和识别模型需另行部署。本地配置、凭据、录音和私人台词库应保存在本机。未配置语音服务时可继续使用桌宠和气泡。
